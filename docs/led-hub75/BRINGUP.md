# Первое включение

Цель: довести картинку с ноутбука до модуля. Это первая веха проекта и
единственная, где есть настоящая неопределённость — всё остальное после неё
становится обычной работой.

Порядок важен: каждый шаг проверяет ровно одну вещь. Если перепрыгнуть, потом
не поймёте, какая из трёх новых сущностей сломана.

## Что нужно

- Модуль `RX2.0-1515-160X80-40S` (160×80, развёртка 1/40)
- Приёмная карта Colorlight 5A-75B
- БП 5 В на 6–8 А
- Патч-корд, шлейф HUB75, кабель питания модуля
- Компьютер с Linux (Orange Pi или любой ноутбук)
- Разово: ПК с Windows для LEDVISION

## Шаг 1. Питание

Ещё до подачи напряжения:

1. Прозвоните +5 В и GND тестером — короткого быть не должно.
2. Проверьте полярность на клеммах модуля. Переполюсовка убивает его необратимо.
3. Питание идёт **и на модуль, и на карту**. У карты свой разъём питания.
4. Земля общая.

Включите БП без нагрузки, убедитесь, что на выходе 5,0–5,2 В, и только потом
подключайте модуль.

## Шаг 2. Сеть

Карта работает на канальном уровне: **у неё нет IP-адреса и она не отвечает на
ping.** Не тратьте на это время. Всё, что нужно, — поднятый интерфейс:

```bash
sudo ip link set eth0 up          # адрес не назначаем, DHCP не нужен
ip link show eth0                 # ждём state UP и LOWER_UP
```

Если в системе есть NetworkManager, уберите интерфейс из-под его управления —
иначе он будет пытаться получить адрес и ронять линк:

```bash
sudo nmcli device set eth0 managed no
```

Шлейф HUB75 втыкается в **входной** разъём модуля (у него два, второй для
гирлянды), на карте — в порт J1.

## Шаг 3. Карта отвечает?

```bash
sudo python3 sender/send.py --iface eth0 --discover
```

Ожидается строка с MAC-адресом, версией прошивки и номером карты. Это первый
настоящий сигнал, что железо живо и связь есть.

Пусто — смотрите шаг 2: линк, порт, питание карты. До прохождения этого шага
дальше идти бессмысленно.

## Шаг 4. Конфигурация развёртки

Пока этот шаг не сделан, **на экране будет мусор, и это нормально**. Карта не
знает, как устроен модуль.

Настраивается разово, с Windows, программой LEDVISION или LEDSetting, режимом
«интеллектуальная настройка». Все входные параметры известны:

| Параметр | Значение |
|---|---|
| Разрешение | 160 × 80 |
| Развёртка | 1/40 |
| Групп данных | 2 |
| Драйвер (chip type) | **FM6363** |
| Выбор строки | сдвиговый регистр **SM5266P** |

Мастер покажет тестовые картинки и спросит, что и где загорелось. По ответам
он выведет схему обхода и запишет её в карту. Настройка остаётся в карте после
выключения — повторять не придётся.

Подробнее и о запасных вариантах — `DESIGN.md` §7.

## Шаг 5. Первая картинка

Начинайте с малой яркости — так меньше шансов что-то спалить, если в питании
ошибка:

```bash
sudo python3 sender/send.py --iface eth0 --pattern corners --brightness 40
```

Ожидается: рамка, красный квадрат слева сверху, зелёный справа сверху, синий
слева снизу, жёлтый справа снизу.

Дальше по порядку:

```bash
sudo python3 sender/send.py --iface eth0 --pattern rgb       # порядок цветов
sudo python3 sender/send.py --iface eth0 --pattern grid      # геометрия
sudo python3 sender/send.py --iface eth0 --pattern gradient  # глубина цвета
sudo python3 sender/send.py --iface eth0 --image photo.jpg --fit cover
```

## Что означает симптом

| Видно | Причина |
|---|---|
| Не светится ничего | Питание модуля, шлейф не в тот разъём, карта без питания |
| `--discover` молчит | Линк, интерфейс не поднят, NetworkManager перехватил порт |
| Мусор, шум, случайные точки | Развёртка не настроена — это шаг 4, до него так и должно быть |
| Полосы `rgb` идут не R-G-B слева направо | Порядок цветов в конфигурации карты |
| Красный квадрат не слева сверху | Поворот или зеркальность — правится в конфигурации |
| Картинка повторяется или занимает половину | Неверный размер или развёртка в конфигурации |
| Часть строк темнее или смещена | Развёртка 1/40 указана неверно |
| Сетка рвётся, строки съезжают | Ошибка в схеме обхода — вернуться к мастеру |
| Градиент идёт ступенями | Глубина цвета или гамма в настройках карты |
| Мерцание, белый уходит в жёлтый | Просадка питания: тонкий провод или слабый БП |
| Экран гаснет через секунду | Карта не получает sync — смотрите pcap, шаг ниже |

## Если непонятно, что уходит в сеть

Запишите кадры в файл и откройте в Wireshark — карта и root для этого не нужны:

```bash
python3 sender/send.py --pcap out.pcap --pattern corners
```

В файле должно быть 82 пакета: один яркости (`0x0A`), 80 строк (`0x55`) и один
sync (`0x01`) последним.

Структура пакетов покрыта тестом, он гоняется без железа:

```bash
python3 sender/test_colorlight.py
```
