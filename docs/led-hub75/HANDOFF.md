## Цель

Настольная/настенная панель на ESP32-S3 с сенсорным экраном: показывает данные
из админки коворкинга (брони, свободные места, статусы комнат) и имеет
сенсорные кнопки, которые шлют действия на сервер. Сервер отдаёт «display
list» — список примитивов отрисовки, устройство их рисует. Вёрстка и кнопки
меняются на сервере без перепрошивки.

## Железо — подтверждено на реальной плате

Плата **Guition ESP32-S3-4848S040**, 4″, 480×480, в корпусе 100×100 мм.
Пользователь получил её, она подключена к компьютеру.

| | |
|---|---|
| Порт | **COM10** (мост CH340) |
| Чип | ESP32-S3 (QFN56) rev v0.2 |
| PSRAM | 8 МБ встроенная, **octal** |
| Флеш | 16 МБ, **quad** |
| Экран | ST7701S, параллельный RGB |
| Сенсор | GT911 по I²C, SDA 19, SCL 45, адрес 0x5D или 0x14, INT/RST не разведены |
| Подсветка | GPIO 38 |
| Микрофона | нет |

Отсюда `board_build.arduino.memory_type = qio_opi`. С неправильным типом PSRAM
не найдётся, и кадровый буфер 480×480 (460 КБ) не создать.

## Что делать — по порядку

**1. Резервная копия заводской прошивки. Обязательно, до любой записи.**

```powershell
python -m esptool --port COM10 --baud 460800 read-flash 0 0x1000000 backup_4848.bin
```

**Сделано 02.11.2026:** копия лежит в `C:\My project\led-hub75-backup\backup_4848.bin`
(SHA256 `7DF219A9…00C3BA`). На 921600 мост CH340 бьёт пакеты — только 460800.

Сохрани файл вне репозитория и скажи пользователю, где он лежит. esptool у
пользователя уже стоит (v5.6.0). На Windows интерпретатор — `python`, не
`python3`.

**2. Поставить PlatformIO и собрать `bringup-4848`.**

```powershell
pip install platformio
cd bringup-4848
pio run -t upload --upload-port COM10
```

**3. Прочитать вывод из порта** и проверить:

- `PSRAM:` около 8 МБ, `Flash:` 16 МБ;
- `экран: ok`;
- `сенсор GT911: найден по адресу 0x5D` (или 0x14).

**4. Попросить пользователя описать экран.** Ожидается по три секунды: углы
(красный слева сверху, зелёный справа сверху), полосы R-G-B слева направо,
градиент без ступенек, затем «Touch the screen» и голубые точки под пальцем.

Если картинка повёрнута — менять `rotation` в конструкторе
`Arduino_RGB_Display`. Если точки не под пальцем — у GT911 переставлены или
отражены оси, править в `gtRead()`.

**5. Только после этого** — перенос основной прошивки на плату: приёмник
пикселей `PixelSink` поверх Arduino_GFX (рисовать в теневой буфер в PSRAM и
копировать целиком, а не по пикселю в живой кадровый буфер), опрос GT911 →
`hitTest()` → POST на `path` кнопки с базовым адресом из настроек.

## Правила, которые выработались

- **Проверять компилятором и тестами, а не на глаз.** После правок в
  `firmware/src` гонять `python firmware/test/compare.py`.
- **Не утверждать «работает», пока не видели на железе.** Говорить отдельно,
  что собрано, а что запущено.
- Действие кнопки — **путь**, не полный URL. Устройство подставляет базовый
  адрес из настроек и не может постучаться на чужой хост. Не ломать это.
- Коммиты — в эту ветку, понятные сообщения. Пушить после каждого шага.

## Что не трогать

`firmware/` под HUB75, `bringup-esp32/`, `sender/` (Colorlight) — это прежние
ветви проекта: светодиодная панель P2 и приёмная карта. Они отложены, но
сохранены намеренно. История решений — в `docs/led-hub75/DESIGN.md`.
