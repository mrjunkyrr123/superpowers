## Цель

Настольная/настенная панель на ESP32-S3 с сенсорным экраном: показывает данные
из админки коворкинга (брони, свободные места, статусы комнат) и имеет
сенсорные кнопки, которые шлют действия на сервер. Сервер отдаёт «display
list» — список примитивов отрисовки, устройство их рисует. Вёрстка и кнопки
меняются на сервере без перепрошивки.

## Железо — подтверждено на реальной плате

Плата **Guition ESP32-S3-4848S040**, 4″, 480×480, в корпусе 100×100 мм.
Пользователь получил её, она подключена к компьютеру.

| | |
|---|---|
| Порт | **COM10** (мост CH340) |
| Чип | ESP32-S3 (QFN56) rev v0.2 |
| PSRAM | 8 МБ встроенная, **octal** |
| Флеш | 16 МБ, **quad** |
| Экран | ST7701S, параллельный RGB |
| Сенсор | GT911 по I²C, SDA 19, SCL 45, адрес 0x5D или 0x14, INT/RST не разведены |
| Подсветка | GPIO 38 |
| Микрофона | нет |

Отсюда `board_build.arduino.memory_type = qio_opi`. С неправильным типом PSRAM
не найдётся, и кадровый буфер 480×480 (460 КБ) не создать.

## Выученное на железе

- **Порт только 460800.** На 921600 CH340 бьёт пакеты (`Corrupt data`).
- **Bounce-буферы обязательны** (`board.cpp`, `SCREEN_W * 10`). Без них запись
  в PSRAM отнимает поток у экрана (PCLK 12 МГц, кадр в PSRAM) — картинка
  мерцает и дрожит вбок. Подтверждено: с ними дрожь ушла.
- **Скорость:** полный кадр ~75 мс отрисовка + ~35 мс вывод. Полная перерисовка —
  только по событию (смена экрана, касание, данные). Бегущая строка, которая не
  влезает по ширине, перерисовывает только свою полосу (`drawBands`, ~28 мс →
  25 кадров/с). Анимацию на весь кадр не делать — вернётся дрожь.
- `PixelSink::hline()` — быстрые заливки и отрезки глифов; по умолчанию по
  точке, так что табло HUB75 рисует как раньше.
- **`compare.py` гоняется локально:** GCC из `winget install
  BrechtSanders.WinLibs.POSIX.UCRT`. В новой оболочке он в PATH сам; в старой —
  перечитать PATH из реестра. `host_render.cpp` на Windows берёт текст из
  UTF-16 командной строки — иначе кириллица приходит в cp1251 и 11 проверок
  ложно падают.
- **`compare.py` не проверяет сишный `hitTest`** — только питоновский
  `R.hit_test`. Так прожил баг: `a["path"] | nullptr` в ArduinoJson 7 всегда
  nullptr, ни одна кнопка не нажималась. Исправлено (`as<const char *>()`);
  хостового теста `hitTest` нет — нужен ArduinoJson на хосте.
- **Подсветка: ШИМ 25 кГц.** На 5 кГц драйвер подсветки свистел; владелец
  подтвердил, что на 25 кГц тихо.
- **Сигнал Wi-Fi на столе слабый:** −74…−84 dBm, изредка `HTTP GET -> -1`.
- **Запросы блокирующие:** пока сервер не отвечает, экран и касания стоят до
  5–8 с. С локальным сервером незаметно; для боевого — кандидат вынести сеть
  в отдельную задачу FreeRTOS.
- Сборка иногда падает вылетом gcc (`Error 3221225477`) на файлах Arduino_GFX —
  не наш код, `flash.ps1` повторяет сам.
- Серые дизайнера на плате выглядят нормально (розового оттенка владелец не заметил).

## Правила, которые выработались

- **Проверять компилятором и тестами, а не на глаз.** После правок в
  `firmware/src` гонять `python firmware/test/compare.py` (на Windows нет C++ — см. выше).
- **Не утверждать «работает», пока не видели на железе.** Говорить отдельно,
  что собрано, а что запущено.
- Действие кнопки — **путь**, не полный URL. Устройство подставляет базовый
  адрес из настроек и не может постучаться на чужой хост. Не ломать это.
- Коммиты — в эту ветку, понятные сообщения. Пушить после каждого шага.
