# Текущее состояние проекта

Файл для передачи контекста между сессиями Claude. Обновлять после каждого шага.
Последнее обновление: 2026-09-05.

## Что решено

- **Сервер: PiPO X9s.** Intel Atom Z8350, **2 ГБ RAM** (проверено в BIOS Aptio), eMMC **32 ГБ** (в UEFI Shell видно ~30 ГБ с тремя разделами старого Linux, пароль от него неизвестен, сносим).
- UEFI **64-битный**: HAOS `haos_generic-x86-64-18.2` успешно загрузился с USB-флешки. Secure Boot выключен.
- Сеть: RJ45 есть, через свитч, интерфейс в HAOS называется `enp0s20u3`. Получил IP `192.168.0.249` по DHCP. Wi-Fi `wlan0` тоже определился, не используем.
- **Панель: PiPO X10** (RK3399, Android, 10"). Ставим приложение HA или Fully Kiosk, см. `docs/05-wall-panel-x10.md`.
- **Orange Pi 3 LTS** не используем. Docker-стек лежит в `docker/` как план Б.
- **Zigbee: стик Sonoff**, модель (P или E) пока неизвестна, стика нет под рукой. Конфиг под оба варианта в `haos/zigbee2mqtt-addon-options.yaml`.
- Проект домашний, не для бизнеса. Цель: разобраться с HA и Zigbee.

## Где застряли

HAOS с первой USB-флешки загрузился, Supervisor поднялся, но **HA Core не докачался**: на флешке осталось 0.3 ГБ, лог Supervisor: `not enough free space` / `no space left on device`.

Попытки обойти:
- HAOS на SD-карту через слот SD → UEFI Shell, слот не загрузочный (blk4/blk5 без fs-алиаса).
- Та же SD-карта через USB-картридер → биос не видит.
- HAOS на USB-флешку 16 ГБ через Etcher → биос её не видит. Причина не ясна: возможно, USB 3.0 флешка, старый биос 2017 г., или запись не прошла. Надо проверить разделы флешки на компе (`Get-Disk`, `Get-Partition` в PowerShell): у правильно записанной будет ~8 разделов, первый `hassos-boot` ~32 МБ.

## Следующий шаг: перенести HAOS на eMMC

Вариант А, без второй флешки. Загрузиться с первой (рабочей) USB-флешки HAOS, дождаться `ha >`, USB-клавиатура, затем:
```
login
which curl unxz dd
lsblk
```
Если все три утилиты есть, а eMMC виден как `mmcblk0` (~29G, три раздела):
```
curl -L https://github.com/home-assistant/operating-system/releases/download/18.2/haos_generic-x86-64-18.2.img.xz | unxz | dd of=/dev/mmcblk0 bs=4M
poweroff
```
Вынуть флешку, включить, HAOS грузится с eMMC. IP смотреть на экране в строке `enp0s20u3`.

Вариант Б, если `unxz` нет. Ubuntu Desktop на рабочую флешку через Etcher, Try Ubuntu, `lsblk`, `xzcat ... | sudo dd of=/dev/mmcblk0 bs=4M status=progress conv=fsync`. Подробно: `docs/02-install-haos-x9s.md`, шаг 3.

## После переезда

1. `http://<ip>:8123` → создать пользователя, дом, часовой пояс.
2. Зафиксировать IP коробки на роутере по MAC.
3. `docs/04-addons.md`: Mosquitto, File editor, `haos/configuration.yaml`. Zigbee2MQTT только когда стик будет в руках.
4. `docs/05-wall-panel-x10.md`: панель.
5. Включить автобэкапы: Настройки → Система → Резервные копии.

## Как работать с Claude

- Облачная сессия (claude.ai/code) не видит локальную сеть и USB. Годится для правки репо и обсуждения.
- Локальная сессия (VS Code, папка `smart-home`) видит флешки в компе и HA по сети `192.168.0.249`. Для управления HA понадобится долгосрочный токен: профиль → Безопасность → Долгосрочные токены доступа.
- Оба варианта читают этот файл первым делом. После значимых изменений обновлять его и коммитить.
