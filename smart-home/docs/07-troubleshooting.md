# Что делать, когда не работает

## Диагностика: три команды

Всё в консоли коробки, в приглашении `ha >`. Префикс `ha` не нужен.

```
core info        # state: running / starting / failed + версия
network info     # адрес, connected, enabled
core logs        # последние строки, ищем ERROR и Traceback
```

Плюс два адреса в браузере:

| Адрес | Что показывает |
|---|---|
| `http://<ip>:8123` | сам Home Assistant |
| `http://<ip>:4357` | Observer: состояние Supervisor, работает даже когда Core лежит |

Правило: если Observer открывается, а 8123 нет, значит железо и сеть живы,
проблема в Core. Если не открывается ни то ни другое, проблема в сети или адрес сменился.

## Порт 8123 не отвечает

1. **Адрес уехал.** IP выдан по DHCP. Проверить `network info`, закрепить IP на роутере по MAC.
2. **Core ещё стартует.** На Atom Z8350 первый старт после онбординга занимает 5-15 минут.
   В `core info` будет `state: starting`. Ждать.
3. **Core в петле перезапуска.** Признак: в `core logs` лог начинается с начала снова и снова,
   каждые несколько минут. На 2 ГБ памяти это почти всегда нехватка памяти при загрузке
   тяжёлых интеграций. Лечится облегчённым конфигом, см. ниже.
4. **Порт занят или конфиг сломан.** `core check` проверит YAML.

## Заставка с логотипом крутится вечно

Сервер отвечает, интерфейс не дорисовывается.

1. Открыть в инкогнито или с телефона — отсекает кэш браузера.
2. `core restart`, подождать 3-5 минут.
3. Если после рестарта стало хуже (порт вообще умер), значит Core не поднимается,
   иди в раздел про петлю перезапуска.

## Мало памяти: облегчённый конфиг

`default_config:` одной строкой включает полтора десятка интеграций. На 2 ГБ
самые опасные из них:

| Интеграция | Чем плоха |
|---|---|
| `stream` | тянет ffmpeg, в логе видно `Setup of stream is taking over 10 seconds` |
| `cast` | сканирует сеть, стучится к телевизорам, в логе `Failed to connect to ... :8009` |
| `ffmpeg` | приезжает вместе со stream |

Решение: заменить содержимое `/homeassistant/configuration.yaml` на
`haos/configuration-lowmem.yaml` из этого репо. Там те же интеграции, но перечислены
поштучно и без тяжёлых. Потом `core restart`.

Как править файл, когда интерфейс не открывается: аддон File editor поставить не выйдет,
поэтому либо аддон Advanced SSH & Web Terminal (тоже нужен интерфейс), либо
через консоль коробки. Проще всего дождаться, пока HA поднимется хоть раз,
и сразу поставить SSH-аддон, чтобы больше не зависеть от интерфейса.

## Нет сети

Симптом в логе Supervisor: `No Supervisor connectivity, delaying version fetch`,
и часы показывают прошлый год.

```
network info
```

- `enabled: false`, `method: disabled` → интерфейс выключен:
  ```
  network update enp0s20u3 --ipv4-method auto
  ```
- Ошибка `device has no carrier` → нет физического линка. Кабель, порт свитча,
  лампочки на разъёмах. Ethernet у этой коробки на внутреннем USB, помогает
  полное обесточивание на 10 секунд с уже воткнутым кабелем.

## Кончилось место

В логе Supervisor: `not enough free space` и `no space left on device`.

HAOS с флешки меньше 8 ГБ не влезает: система и HA Core занимают около 5 ГБ.
Нужна флешка от 16 ГБ, а лучше переезд на eMMC (`docs/02-install-haos-x9s.md`, шаг 3).

## База не закрылась корректно

`The system could not validate that the sqlite3 database was shutdown cleanly`.

Последствие выключения по питанию. HA чинит сам. Чтобы не повторялось,
выключать через Настройки → Система → Выключить, или командой `host shutdown`.

## Косметика, на которую не надо смотреть

- `Failed to load integration for translation: Invalid domain ...` — переводы интерфейса
- `i2c_designware ...: timeout in disabling adapter` — шум этой платы при загрузке
- `SyntaxWarning: 'return' in a 'finally' block` — предупреждение библиотеки
