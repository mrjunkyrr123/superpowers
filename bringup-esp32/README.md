# Первое включение панели на ESP32

Минимальная прошивка: ни WiFi, ни сервера, ни админки. Крутит тестовые таблицы
по три секунды каждая и пишет в Serial, что сейчас на экране.

Это повторение проекта
[schematik.io/projects/esp32-rgb-matrix-display-wgjb](https://www.schematik.io/projects/esp32-rgb-matrix-display-wgjb),
только вместо статичной заставки — набор таблиц, по которым видно, что именно
не так, если что-то не так.

## Что нужно

| | |
|---|---|
| Панель | 64×32, HUB75, развёртка 1/16 (в том проекте — Waveshare, шаг 5 мм) |
| Плата | ESP32 devkit |
| Питание | 5 В, минимум 4 А, **отдельный БП на панель** |
| Буфер уровней | не обязателен для пробы, см. ниже |

## Сборка

```bash
pio run -e panel64x32 -t upload && pio device monitor
```

## Подключение

Распиновка берётся из `../firmware/src/panel_pins.h` — один источник на оба
проекта. Полная карта соединений: `../docs/led-hub75/WIRING.md`.

| HUB75 | ESP32 | | HUB75 | ESP32 |
|---|---|---|---|---|
| R1 | 25 | | A | 33 |
| G1 | 26 | | B | 4 |
| B1 | 27 | | C | 16 |
| R2 | 14 | | D | 17 |
| G2 | 13 | | CLK | 18 |
| B2 | 32 | | LAT | 23 |
| GND | GND | | OE | 19 |

**Почему не распиновка по умолчанию из библиотеки.** Та вешает G2 на GPIO12, а
это вывод выбора напряжения флеш-памяти при старте. Притянутый панелью к
высокому уровню, он не даёт ESP32 загрузиться — плата молчит с подключённой
панелью и оживает без неё. Распиновка выше GPIO12 не трогает.

**Питание панели — только от отдельного БП.** На странице проекта тут
противоречие: в таблице соединений VCC панели идёт на вывод 5V платы ESP32, а в
тексте шага 3 написано этого не делать. Верен текст. Панель 64×32 на белом поле
берёт до 3,5 А, дорожка на девките столько не выдержит. Землю БП и землю ESP32
соединить обязательно.

**Буфер уровней.** Проект обходится без него и предлагает добавить, только если
картинка нестабильна. Для пробы на коротких проводах так и правда обычно
работает. Для постоянной эксплуатации ставьте `74AHCT245` — именно AHCT, у серии
HC порог переключения выше 3,3 В.

## Что проверяет каждая таблица

| Таблица | Что проверяет | Что значит поломка |
|---|---|---|
| `corners` | Поворот и зеркальность | Красный квадрат не слева сверху — картинка повёрнута |
| `rgb` | Порядок цветов | Полосы не R-G-B слева направо — перепутаны каналы |
| `grid` | Схему развёртки | Разрывы, съехавшие строки — неверная развёртка |
| `rows` | Порядок строк | Переход не плавный — строки идут не по порядку |
| `gradient` | Глубину цвета | Ступени вместо плавного — мало бит на канал |
| `text` | Вывод текста | — |
| `white` | Питание под нагрузкой | Уход в жёлтый, мерцание — просадка, тонкий провод или слабый БП |

Яркость при старте 60 из 255 — специально мало: если в питании ошибка, на малом
токе она обходится дешевле. Поднимать после того, как всё заработает.

## Эксперимент: гибкий модуль P2 160×80

```bash
pio run -e p2mod160x80 -t upload && pio device monitor
```

**Это проверка гипотезы, а не рабочий режим.** Модуль
`RX2.0-1515-160X80-40S` рассчитан на приёмную карту, а не на микроконтроллер.
Шансы есть, гарантии нет — три неизвестных подряд:

1. **Драйвер столбцов `FM6363B`** требует инициализации конфигурационных
   регистров, и в библиотеке его нет: там `SHIFTREG, FM6124, FM6126A, ICN2038S,
   MBI5124, DP3246`. Ставим `FM6126A` как ближайшего родственника по семейству
   Fuman. Совпадёт ли последовательность — неизвестно.
2. **Драйвер строк `MW5566P`** — класс `SM5266P`, и такой `line_decoder` в
   библиотеке есть. Но писался он под развёртку 1/32 и 64×64, а у нас 1/40 и
   80 строк.
3. **Память.** 160×80 при 8 битах цвета не помещается в ESP32-WROOM, поэтому
   глубина урезана до 5 бит. Если `begin()` всё равно вернёт ошибку —
   уменьшайте `COLOR_DEPTH` в `platformio.ini` дальше.

Ожидаемый исход при неудаче — мусор на экране или тишина, без вреда для железа.
Если на `corners` проступит хоть что-то осмысленное — гипотеза живая и стоит
копать дальше.
